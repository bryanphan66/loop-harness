Nghiệm thu khách hàng (UAT) - mục tiêu anh Nghĩa

Vòng lặp UAT: chuyển từ Google Sheet sang Plane

UAT (User Acceptance Test - khách kiểm thử xem tính năng có đạt không). Khách chấm từng tính năng, cái nào lỗi thì đẻ việc con cho team sửa, sửa xong báo lại, lặp tới khi khách duyệt - và mọi bước tự đồng bộ với Git để không phải chép tay 2 nơi.

📄

Hiện tại khách giao tiếp ở đâu? -> Google Sheet

Đúng vậy. Bây giờ khách nghiệm thu trên một UAT sheet (Google Sheet): khách ghi Đạt/Chưa đạt và nhận xét vào các cột. Mục tiêu của anh Nghĩa là dời hẳn việc này sang Plane.

Google Sheet (đang dùng)  ->  Plane (mục tiêu)

Vòng lặp UAT - 1 tính năng đi qua các bước

Bước 0 - Danh sách

Task cha "Trang danh sách khoá học" ở trạng thái Đang UAT

Mỗi tính năng = 1 task cha trong danh sách nghiệm thu (Sheet nay, Plane sau).

Bước 1 - Khách chấm

Khách test tính năng và cho kết quả

Khách dùng thử rồi chọn: đạt hay chưa đạt.

Khách hàng
ĐẠT ✓

Task tự chuyển Done -> đẩy về Git

Trạng thái Done tự đồng bộ về Git (issue GitHub đóng lại). Xong, hết vòng.

CHƯA ĐẠT ✕

Khách comment + đẻ task con

Khách ghi nhận xét (VD "nút Tìm kiếm không ra kết quả") rồi tạo task con Bug / Enhancement. Task cha vẫn để Đang UAT.

Bước 2 - Team sửa

Dev sửa xong toàn bộ task con -> đánh dấu "Dev đã fix"

Khi mọi task con của cha đó xong, đặt cha sang trạng thái/nhãn "Dev đã fix" để báo khách test lại. lọc được -> đồng bộ Git

Team dev
🔁 Lặp Bước 1 - 2 (thường 2-3 vòng) đến khi khách chấm ĐẠT
✓ Khách duyệt ĐẠT -> Task Done -> đồng bộ Git -> kết thúc tính năng

Vì sao chuyển sang Plane - và điều anh Nghĩa lo

📄 Google Sheet (đang dùng)

Khách ghi trực tiếp vào cột

  • Lọc (filter) rất tiện: cột "dev status" lọc cái rụp ra task nào đã fix chờ test lại.
  • Khách quen thao tác, dễ nhìn tổng thể.
  • Nhược: tách rời Git, phải chép tay qua lại; không gắn được code/issue.

🗂️ Plane (mục tiêu)

Khách comment thẳng trên task

  • Đồng bộ 2 chiều với Git tự động ở mỗi bước - dev chỉ nhìn 1 nơi.
  • Task con Bug/Enhancement + quan hệ cha-con là tính năng có sẵn.
  • Comment của khách gắn thẳng vào task, có lịch sử rõ ràng.
💡 Lo lắng của anh Nghĩa "comment thì không lọc được task đã fix" -> Plane khắc phục: dùng Trạng thái / Nhãn "Dev đã fix" thay cho comment -> lọc được ngay, bằng hoặc hơn sheet.

Plane đáp ứng tới đâu

Có sẵn / đã làm

  • Danh sách task + task con Bug/Enhancement
  • Comment của khách trên task
  • Lọc theo trạng thái / loại (thay cột sheet)
  • Đồng bộ Git -> Plane (issue, comment mới, cha-con)

Cần tự động hoá (tạm làm tay OK)

  • Đạt -> tự chuyển Done
  • Chưa đạt -> tự tạo task con
  • Xong hết con -> tự báo cha "đã fix"

Còn thiếu / cần kiểm

  • Comment cũ không tự kéo về (chỉ comment mới)
  • Xoá comment chưa đồng bộ ngược
  • Chiều Plane -> Git cần bật + test thật

Mục tiêu xa của anh Nghĩa

Anh chat trong Telegram -> Agent (từ goclaw) -> Tự comment / reply khách trên Plane

Đích cuối: anh chỉ nói chuyện với 1 agent (trợ lý AI) trong Telegram, nó tự trả lời khách ngay trên Plane; về sau gắn hẳn agent CS (chăm sóc khách hàng) vào Plane. Con agent này làm từ goclaw - Plane không tự đẻ agent, chỉ mở sẵn chỗ (API comment) để agent goclaw cắm vào. Trước mắt cứ đi từng bước, phần nào chưa auto thì làm tay vẫn ổn.
